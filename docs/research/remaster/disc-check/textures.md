# Kya: Dark Lineage (PS2, CDEURO) texture survey

Generated by `kya_tex.py` (survey + GS-emulated decode), `report.py` (tables), `export_samples.py` (samples).
Re-run: `python3 kya_tex.py <path to CDEURO> out && python3 report.py > tables.md && python3 export_samples.py`
(~20 s total, stdlib + Pillow for PNG only).

## How the data is laid out (reused from repo code)

- **BNK** (`src/EdenLib/edBank/sources/edBankFile.cpp`): `KNAB` header at +8, fileCount @0x28, entry table @(+0x30 value)+8
  (16 B: offset,size,?,crc; offsets file-relative), name tree @(+0x38)+8 (TreeInfo_Recurse format, `dir\.ext\name`),
  name-index -> file-index table @(+0x3c)+8. All 744 banks on this disc are unpacked (flags&1 == 0, no LZ77).
- **G2D** (`ed3D.cpp` ed3DPrepareG2DManageStruct/ed3DPreparePointer): 16-byte GXD header (`.G2D` at +12, total length at +8),
  then chunks `*2D*`{TEXA,LAYA,MATA{HASH,MAT.}}, `PALL`{HASH,PA32}, `T2DA`{HASH,T2D.}, `PSX2`, `ANMA`, `REAA`{REAL}.
  Every pointer is a file-start-relative offset (REAL lists them), so no relocation pass is needed offline.
- **Graph** (`port/KyaTexture/src/Texture.cpp`): MAT. -> LAY.(bHasTexture, paletteId, pTex) -> TEX.(hash->T2D. bitmap,
  bHasPalette = palette count, N palette hashes -> PA32). Bitmap/palette header = {w,h,bpp,maxMipLevel,pPSX2}.
- **Pixels**: the palette's PSX2 DMA list uploads mips then CLUT (bitmap's own list if unpalettised); each transfer =
  A+D BITBLTBUF/TRXPOS/TRXREG + REF tag to raw data. Sampling state = TEX0_1 in the material's render command buffer.
  Decoding = write transfers into an emulated 4 MB GS memory with DPSM swizzle, read back with TEX0 PSM/TBP0/TBW, CLUT
  from CBP (CSM1, CT32, 256-entry bit3/4 swap). Swizzle tables copied from the PCSX2 `GSTables.cpp` in the repo.
- 1 `.fon` (MENU/MENUDATA.BNK medium.fon) embeds a full G2D after its glyph table; handled.

## Checking the decode

- Checked by eye in contact sheets and single PNGs, looked at with the Read tool: KYATITLE logo, Kya body atlas (jeans/face/hair),
  BONUS 512x512 CT32 artwork, level foliage/wood/stone, FX sprites, font glyph sheet, 3 palette variants of one wood texture.
  All T8-uploaded-as-CT32, T4-as-CT32, T4/T8 native, CT32 and multi-transfer (BONUS, 3 strips via TRXPOS) paths look correct:
  tiles are continuous, cutout edges are clean, and there are no block/column scrambles.
- 0 parse errors, 0 decode errors across 3,093 G2D files / 11,081 bindings.

## Caveats

- **Alpha is PS2-range**: every decoded texel has A <= 0x80 (max seen 0x80). Exported PNGs use A*255/128 (clamped).
  TCC=1 on every material, so texture alpha is always sampled. 17 combos have A=0 everywhere (probably additive FX,
  so blending ignores alpha). Keep that in mind: a naive alpha-premultiply would make them invisible.
- **Palette hash spill**: PA32 palettes smaller than the CLUT block (2..128 entries) are still uploaded as a full 16x16/8x2
  CT32 block. The transfer reads past the palette into unrelated file bytes, so the palette is hashed only on its w*h*4
  payload. Even so, most "distinct palettes" per image give identical pixels (the entries differ only where no texel uses
  them). The decoded-output table is the one to trust: 95.7% of images have a single real look, and 3,215 unique RGBA textures in total.
- **Mip count**: the header `maxMipLevel` undercounts. 451 images claim 2 levels but upload 3 (the Texture.cpp comment
  says the same). The 173 BONUS 512x512 CT32 images claim 1 level and upload 3 transfers, but those are strips of a single level
  (a DMA size limit), not mips. The tables report the header value.
- **Multi-layer materials** (137 layer-1 bindings, e.g. env/reflection layers): the material command buffer holds only
  layer 0's TEX0. For those, TEX0 is rebuilt from the layer's own upload (TBP0 = DBP, CBP = palette DBP). That affected only 2
  unique combos.
- Only mip level 0 is decoded. CT16/CT24/CSM2/T8H/T4HL/HH code paths exist but never occur on this disc (all CLUTs are
  CT32 CSM1, all textures are T4/T8/CT32). CT16's alpha bit is mapped as 0x80/0, which is untested.
- "Unique image" = sha1 of level-0 transfer bytes. The same pixels stored with a different upload DPSM would be counted twice
  (rare). The per-folder "unique" column is unique within that folder. 1,006 images repeat across folders, 205 in more than 5.
- UV-scrolling textures (ANIM ST, 684 bindings, 6%) and ANMA-animated materials exist. An upscaler must keep tiling/wrap
  (seamless edges) for the many 128x128 tiling textures and keep 1-bit cutouts hard (41.8% of combos).
- No per-texture names exist in G2D (only 8-byte hashes). Sample names/categories come from the G2D entry path plus
  a visual pick from contact sheets (local only, not committed: game data).
